# 게임 재접속

## 동작 규칙

- 연결이 끊겨도 참가자는 180초 동안 방에 남는다. 이 시간 안에 돌아오면 현재 상태로 복귀한다.
- 유예 시간이 끝나면 참가자를 제거하고 진행 중인 게임을 종료한다. 남은 참가자는 대기방으로 돌아간다.
- 명시적인 나가기는 유예 없이 처리한다.
- 발언 시간은 연결 상태와 관계없이 흐른다. 서버가 마감을 처리하고 투표로 전환한다.
- 투표는 기본 30초다. 미제출은 기권으로 기록하며 비동의 수에는 더하지 않는다.
- 기존 획득 기준을 유지한다. 3명 게임은 찬성 1표, 4명 게임은 찬성 2표가 필요하다. 최초 실패 시 한 번 재투표한다.
- 시간 연장은 기존처럼 한 번, 120초다.

`game.reconnect-seconds`, `game.speaking-seconds`, `game.voting-seconds`로 시간을 조정한다. 투표 30초는 이번 구현의 기본값이며 실제 플레이 테스트에서 조정한다.

## 상태와 연결의 책임

`GameProgress`는 마감 시각, 투표, 결과, 상태 버전을 보관한다. `GameService`는 권한과 게임 단계를 검사하고 상태를 변경한다. `GameRoomService`는 참가·퇴장·유예 만료를 담당한다. `GameSseService`는 연결과 전송만 담당한다.

상태 변경은 방 객체의 모니터 안에서 처리한다. 요청과 스케줄러가 같은 잠금을 사용하므로 마지막 투표와 시간 만료가 겹쳐도 점수를 두 번 반영하지 않는다. 다른 방은 별도로 진행한다. 1초 주기의 스케줄러가 서버에 저장된 절대 마감 시각을 확인한다.

## 복구 프로토콜

게임 화면은 `game-state` SSE 이벤트를 구독한다. 이벤트 `id`는 방 단위 증가 번호이며 본문의 `revision`과 같다. 본문은 현재 게임 상태 전체다. 새 연결에도 전체 상태를 보낸다.

클라이언트는 마지막 적용 번호보다 큰 상태만 반영한다. 오래된 연결의 응답도 무시한다. 놓친 이벤트를 순서대로 재생하지 않으므로 퍼즐 증가, 모달, 지연된 화면 전환을 다시 실행하지 않는다. 번호가 건너뛰어도 전체 상태이므로 적용할 수 있다. `Last-Event-ID`를 이용한 이벤트 이력 재생은 제공하지 않는다.

복구 상태에는 단계·순번·발언자·카드·마감 시각·투표 제출자 ID·최근 집계·최종 순위가 포함된다. 투표 내용은 개별 참가자에게 공개하지 않는다. 투표 요청에는 snapshot의 `votingRound`를 함께 전달하며, 이전 투표 차수에서 늦게 도착한 요청은 거부한다. 대기방의 기존 이벤트는 호환성을 위해 유지한다.

## 검증

Java 17에서 다음 명령으로 외부 DB 없이 실행한다.

```sh
./gradlew test --tests '*GameRecoveryTest' --tests '*GameConnectionTest'
```

운영 설정을 읽는 기존 `contextLoads` 테스트는 위 명령에 포함하지 않는다. 테스트는 시간 만료의 중복 처리, 기권과 재투표, 권한, 중복 투표, 상태 복사, 재접속 유예를 확인한다.

## 운영 범위

현재 방과 연결은 단일 프로세스의 메모리에 있다. 서버 재시작을 넘는 복구나 여러 인스턴스 간 상태 공유는 지원하지 않는다. 다중 인스턴스로 확장할 때는 방 소유권, 상태 저장, 버전 발행을 함께 옮겨야 한다. SSE는 장시간 연결이므로 프록시 버퍼링과 유휴 제한도 배포 환경에서 확인해야 한다.

배포 전에는 실제 기기 3~4대로 앱 전환, 네트워크 단절, 마지막 투표 직전 재접속, 3분 만료, 결과 화면 복귀를 확인한다. 단위 테스트만으로 모바일 네트워크와 프록시 동작까지 검증되지는 않는다.
